## Verified baseline and implementation boundary

PR33 remains **82a0053bf64e680554afe5a178576f9c017b1fc0**. `public/atlas/engine.js` blob **67a3d57460fe08d0b9b515ea18e64e5926d98285** was checked against the parent's read-only investigation. It is a custom Three.js r128 globe, not a conventional tiled-map widget. `loadEarth` loads local Natural Earth masks; `planetMaterial` binds textures; `applySet` replaces generated material textures. `S`, `urlFor`, `parseHash` and `syncURL` own relevant state/URL transitions.

**Do not replace `tBase` with colour imagery.** Its red channel is sampled as a land/water mask in both generation and surface shading. Add a separate basemap imagery sampler and validated mode uniform/state; preserve the mask, relief, pick geometry and existing content overlays. Define how the chosen imagery survives procedural rebakes and `applySet`. Texture availability must not trigger pack reload, recentering or a new research location.

## User-facing behavior and state contract

- **Current** is the default, retaining the present appearance. Clarify in help that “Current” means the existing atlas style, not live imagery.
- **Satellite** uses a named, dated composite with visible attribution and resolution limits. It is modern reference imagery, not a reconstruction of ancient terrain, live imagery or street-level photography.
- **Road-map** must honestly describe its detail. A coarse Natural Earth cartographic view can be an explicitly labelled interim option, but does not fulfill detailed-road coverage. Do not silently substitute it or claim the full request complete. Show a clear limited/unavailable state until the selected road implementation is supported.
- Explain near the chooser: **“Modern reference basemap; not ancient geography or evidence for proposed scriptural locations.”** Existing uncertainty badges, citations and source wording stay visible. Do not infer Earth coordinates for BoM models, schematic places, visions or currently unlocated records.
- Earth-only eligibility: enable for the physical Earth globe, not other planets, symbolic realms or internal-geography schematics. Retain a per-pack Earth preference across temporary non-Earth views without applying it there; no imagery requests for ineligible worlds. Returning to Earth restores that preference.
- Switching preserves camera pose/zoom, selected world/site, open cards, reading group, timeline range, layer filters, routes, event selection and evidence links. It changes the base appearance only; do not reuse content-layer toggles for the mode.
- Proposed URL key `basemap=current|satellite|road`, omitted for Current. Parse an allowlisted enum; unknown, duplicate or malformed values normalize deterministically to Current. Never accept a URL/provider endpoint from the hash. Round-trip all existing hash fields unchanged. Explicit user mode choices should create one navigable history entry; startup restoration, normalization and failure fallback replace rather than push. Integrate with existing history handling so Back/Forward restores the full prior view without loops, extra entries or stale async writes. URL state takes precedence over an optional saved preference; do not invent a new storage dependency to deliver the toggle.
- Loading UI distinguishes requested from displayed mode. Keep the current valid frame during loading. On failure, show Current with a concise accessible explanation and retry control, normalize mode/URL using replaceState, retain all content state, and avoid repeated automatic retry loops. A failed old request must never reset a newer successful selection.

## Rendering, projection and resource requirements

1. Separate mode selection from texture loading and from procedural terrain generation. Use a monotonic request/world generation token: only the latest request for the still-current eligible world can install a texture or change displayed mode. Cancel when possible; stale success/failure callbacks must be harmless and release resources.
2. Keep bounded caches and a documented memory budget. Query actual GPU limits; select capped texture dimensions before allocation, account for decoded pixels/mipmaps and simultaneous old/new textures, and release superseded GPU textures/material references. Handle image decode/CORS/context-loss failures without a blank globe or leaked resources. Do not assume a high-resolution master can be uploaded on phones.
3. Verify texture orientation, longitude convention, latitude mapping, colour-space handling, antimeridian seam and polar treatment against existing globe UVs and approved anchors. Do not infer compatibility from an image's aspect ratio alone. Raster Web Mercator tiles require correct reprojection or globe tile geometry, polar limits, seam handling and bounded visible-tile requests; they are not an equirectangular texture to stretch over the sphere. Labels/roads must stay legible at their supported zoom and not be reported as ancient routes.
4. Retain marker picking, route elevation and card layering. Do not alter research coordinates to compensate for an imagery alignment bug. Confirm the shader's lighting, relief and water treatment do not distort the alternate maps or destroy credit/label contrast. Preserve Current exactly unless a separately reviewed change is necessary.
5. Asset manifest must identify source, license/terms URL, credit, retrieval date, observation/composite date, projection, processed dimensions/hash and any processing. Credits must remain visible and readable on desktop and phone, not hidden behind a panel or off-screen. Provider requests and any referrer/cache implications belong in the user-facing disclosure when applicable.
