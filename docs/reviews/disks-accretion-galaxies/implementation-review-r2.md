## R2-C1 — Medium: malformed records silently preserve a forced hold or erase an unknown original hold

Exact evidence: [sandbox-state.ts:197–237](https://github.com/mckayec/universe-sandbox/blob/4f296bf492695ad1d8beb7fbbf9c5061a7c50fac/src/sandbox-state.ts#L197), [history.ts:155–162](https://github.com/mckayec/universe-sandbox/blob/4f296bf492695ad1d8beb7fbbf9c5061a7c50fac/src/state/history.ts#L155). `restoreSavedInfall` returns `undefined` for any primitive, equating a present corrupt record with no capture. `restoreInfalls` then continues without clearing the serialized forced hold. A saved star with `holdStage:true, infall:7` (also false or a string) becomes held with no capture. `advanceStar` returns early at its hold check. Body validation does not reject this nested data.

Separately, `held = raw.heldStage === true` accepts an absent/nonboolean original-hold field as false. An otherwise valid object with missing or string-valued `heldStage`, whose eater is missing, silently clears the body's hold; the real original state is unknown. It cannot truthfully be reported as restored. The same coercion is stored for later cancellation if the record resumes.

**Required fix:** distinguish a genuinely absent legacy record from a present malformed record. Validate record shape and boolean `heldStage`. If the original flag has been lost, do not guess it; reject the corrupt record/snapshot through a documented recovery path that preserves the prior universe, or explicitly report a documented user-visible recovery policy. Preserve compatibility for genuine legacy absence; null currently behaves as legacy and any change needs an explicit compatibility decision. Tests must cover primitives, arrays/empty objects, missing/nonboolean original flags and both originally held/unheld cases. Do not promise exact original-hold restoration when the data no longer contains that information.

## R2-C2 — Medium: resumed capture relies on a second serialized flag instead of establishing its invariant

Exact evidence: [history.ts:161](https://github.com/mckayec/universe-sandbox/blob/4f296bf492695ad1d8beb7fbbf9c5061a7c50fac/src/state/history.ts#L161) only assigns `body.infall`. `restoreBody` takes `saved.holdStage` independently. A valid capture record with top-level `holdStage` missing/false resumes without holding stellar evolution. This differs from `beginInfall`, which always sets `food.holdStage=true`. The simulation still calls `advanceStar`; that function's normal hold guard checks `holdStage`, not `infall`.

**Required fix:** when a validated record resumes, set `body.holdStage=true` and preserve the original boolean exclusively in `infall.heldStage`; cancellation restores that original value. Add tests with top-level true/false/absent for each original boolean. While active, all must be held; after cancellation each must return to its original boolean semantics. This is an invariant-hardening defect for inconsistent inputs, not a claim that current `snapshotUniverse` omits its flag.
